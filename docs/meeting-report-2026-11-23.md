# 회의 보고 — 프런트 API 연동 및 QA 개선

## 보고 요약

백엔드·AI 저장소 수정 없이 프런트 API V2 계약, 사용자 흐름, 오류 처리를 정비했다. 구현·모의 응답 검증과 실제 운영 서버 성공은 구분한다. 운영 서버에 없는 API는 완료로 표기하지 않으며, 사용자 결정에 따라 저장 음식·후기를 준비 중으로 안내한다.

## 이 대화에서 진행한 작업

- API V2에 맞춰 프로필·동의, 업로드·스캔 상태/결과, 기록 페이지 조회·수정·삭제·식당 연결, 식당 검색, 저장 음식, 후기·신고, 직원 답변, 저장 카드, 환율 어댑터와 화면 연결을 점검·보완했다.
- 판정 근거에서 확인된 정보와 추정 정보를 구분하고, 포함 확률은 caution·적용 프로필·유한한 0–100 값 조건에서만 표시하도록 했다. 검증되지 않은 정확도나 데이터 수치를 만들지 않았다.
- 한식 앱 소개, 직원에게 재료 확인하기, 주문 카드 통합, 제외가 어려울 때 대체 음식 요청, 개인화 알레르기 질문, 결과 목록 뒤 큐레이션 동선을 반영했다.
- 최신 main과 기능 브랜치를 통합하고 배포했다. 앞선 배포 기록: `f3cced2`, `24302d8`, `2b33c70`.
- 사용자가 로그인·동의를 완료한 계정에서 읽기 중심 QA를 진행했다. 인증 만료 시 401 → 토큰 갱신 → 재요청 성공을 확인했다.
- 홈·지도·카드·큐레이션·촬영 진입·기존 결과·마이페이지를 Chrome Console/Network와 함께 확인하고 16개 개선 항목을 정리했다.

## 검증과 한계

- 자동 검사: HTTP 계약 86개 및 업로드 인증 격리·토큰 갱신 동시성 검사, V2 결과/확률/환율 검사, 청크 복구·라우팅·식당 중복 제거 검사, 타입 검사·프로덕션 빌드·데모 검사.
- 이 환경의 `pnpm build` 런처는 출력 없이 대기해 중단했다. 이미 설치된 동일 빌드 실행 파일 `node_modules/.bin/vite build`와 `tsc --noEmit`으로 검사했다.
- 로컬 브라우저: 저장 음식·내 후기 준비 중 표시와 요청 0건, 아랍어 안내, 제외 재료 미선택 시 비활성 → 선택 후 활성, 대체 음식 요청, 닫기, 기기 가게 저장/목록/해제/빈 상태, 명시적 새로고침 복구를 확인했다. 테스트는 명시적 fixture이며 실서버 성공으로 계산하지 않는다.
- 기존 번역 fallback은 남아 있다. 중국어 간체·일본어·스페인어 각 287개, 번체 164개이며 기존 영어 fallback과 아랍어 RTL을 유지한다. 전체 7개 언어의 실사용 검수 완료를 의미하지 않는다.

## 운영 API 차단 및 남은 검증

| 항목 | 현재 상태·이유 |
| --- | --- |
| `/saved-menus` | 인증된 배포 요청에서 404. 준비 중 처리; 서버 저장 완료 아님 |
| `/reviews/me`, `/stores/{storeId}/reviews` | 배포 요청에서 404. 후기 조회·작성·신고 진입을 비활성화; 공개 후기 실검증 미완료 |
| `/exchange-rates` | 배포 요청에서 404. 요청 중단, 기존 고정 참고 환산을 명시 |
| 직원 사실 답변·공개 후기·탈퇴 | 공용 판정/공개 데이터 또는 계정에 영향을 주므로 실제 쓰기 검증을 수행하지 않음 |
| 새 이미지 업로드 → AI 분석 → 결과 | 새 테스트 이미지로 수행하는 운영 전 과정은 미검증 |
| 모바일 카메라·위치 권한 거부·오프라인·전체 번역 | 별도 실기기/언어별 검증 필요 |

서버에 없는 동작을 프런트로 성공 처리하지 않았다. 향후 해당 API 배포를 확인한 뒤 `src/app/featureAvailability.ts`를 변경하고 실서버 검증을 진행할 수 있다.
