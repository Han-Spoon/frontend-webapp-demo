# 사용자 흐름

## 시작과 로그인

1. `/` 랜딩에서 한스푼의 메뉴 번역·식단 확인·직원 소통 가치를 확인한다.
2. “한스푼 시작하기”를 눌러 `/login`으로 이동한다.
3. 연령 구간을 선택한다. 만 14세 이상은 Google 계정으로 로그인한다. 만 14세 미만은 법정대리인이 약관 전문을 이메일로 받고 명시적으로 동의한 답장을 운영팀이 확인한 뒤 발급한 승인 코드를 입력해야 Google 로그인으로 진행한다. 이메일·비밀번호 회원가입과 다른 소셜 로그인은 제공하지 않는다.
4. 서버에서 최신 약관 동의 상태를 확인한다. 필수 서비스 이용약관·개인정보 수집·이용·민감정보 처리 동의가 없으면 `/terms`로 이동한다.
5. 필수 문서마다 끝까지 읽고 개별 동의한다. 「전체 동의」는 읽지 않은 필수 문서를 순서대로 열고, 모두 동의하면 선택 마케팅 항목까지 켠다. 선택 항목은 별도 토글·본문 보기와 거부가 가능하다.
6. 서버에 문서 버전과 4개 동의 결정을 저장한 뒤, 기존 프로필이 있으면 홈으로, 없으면 온보딩으로 이동한다. 저장 실패 시 다음 단계로 진행하지 않는다.

랜딩과 로그인에서 언어를 바꿀 수 있고 선택은 두 화면과 이후 앱에 이어진다. Google ID Token과 연령 구간을 `/api/v1/auth/google`로 전달한다. 만 14세 미만의 경우 서버가 승인 코드·약관 버전을 먼저 확인하고 Google 토큰을 검증하며, 보호자 승인으로 필수 동의를 기록한다. 운영팀의 이메일 발송·답장 확인·승인 코드 등록은 수동 운영 절차다.

마이페이지 설정에서 약관 본문을 다시 볼 수 있다. 만 14세 이상은 선택 동의를 바꾸거나 철회할 수 있다. 만 14세 미만은 법정대리인이 이메일로 철회·정보주체 권리 행사를 요청하고, 서버는 아동의 자체 동의 변경을 막는다. 서버가 동의 버전을 바꾸면 재동의가 필요하다. 온보딩은 언어 → 국가 → 식단 3단계이며, 식단에 해당 사항이 없으면 「해당 없음」을 선택한다.

## 로그인 없는 시연 동선

랜딩 또는 로그인 화면의 「로그인 없이 시연하기」는 연령·Google 계정을 묻지 않고 데모 약관 → 온보딩 → 홈으로 이어진다. 데모에서 고른 약관 결정은 서버에 전송하지 않는다. 프로필과 기록은 `src/app/demo/`의 fixture 및 이 브라우저의 로컬 저장소만 사용한다. 새 시연을 시작하면 이전 데모 프로필과 기록을 초기화하고, 온보딩 완료 후 프로필은 새로고침해도 유지된다. 시연 지도는 외부 지도 키 없이 fixture 위치 개요와 선택 가능한 식당 핀을 보여준다. 로그인 화면의 「Google 로그인으로 전환」은 데모 세션을 종료하고 기존 운영 동선으로 돌아간다. 이 동선은 실제 아동 계정 생성이나 개인정보 처리 동의 절차를 대신하지 않는다.

## 식당을 찾는 중

1. 홈에서 5개의 식당 소개/문화 콘텐츠 캐러셀을 본다. 캐러셀은 5초마다 자동 이동하며 모션 감소 설정에서는 자동 이동하지 않는다.
2. 홈에서 청담·부산·강남/역삼 등 18개 지역 칩을 선택하고, 해당 지역 중심 주변의 실제 가게를 지도에서 확인한다. 처음 진입하면 첫 버튼인 청담이 선택되며 일반/데모 홈 모두 동일하다.
3. 홈의 지도 핀으로 가게를 바꾸고, 선택 가게 카드나 전체 지도 버튼에서 같은 검색 중심을 유지한 채 풀스크린 `/map`으로 이동한다.
4. 풀스크린 지도 핀을 누르면 식당 상세 바텀시트가 올라온다.
5. 상세에서 입점/전체 레시피 인증 여부, 같은 프로필의 후기, 찜을 확인한다. 입점 식당은 ‘내 프로필로 메뉴 보기’, 그 외에는 ‘이 식당 메뉴 스캔’으로 이어진다.
6. 홈 하단 ‘한 끼가 여행이 되는 곳’에서 선택한 동네의 실제 식당 후보를 사진 카드로 둘러본다. 최대 6곳의 상호·업종·주소를 보여주며 클릭하면 해당 식당이 선택된 지도로 이동한다. 개인화/안전 순위가 아니며 현재 사진은 표시된 메뉴·공간 참고 이미지다. 상세 정책은 `restaurant-recommendations.md`를 따른다.

홈은 지역 칩에 대응하는 중심 좌표를 `POST /api/v1/stores/candidates`에 보내 반경 1km의 실제 가게를 최대 20곳 조회하며 위치 권한을 요구하지 않는다. 홈에서 `/map`으로 이동하면 전달받은 지역 중심 좌표로 즉시 시작하고, 하단 지도 탭에서 직접 `/map`에 진입한 경우에만 브라우저 현재 위치를 먼저 조회한다. 지도를 옮기면 `dragend` 시점의 중심 좌표로 후보를 다시 조회한다. 후보 응답으로 지도 위치를 다시 맞추지 않아 요청이 반복되는 것을 막고, ‘내 위치’ 버튼은 현재 위치가 아직 없으면 그 시점에 위치 권한을 요청한다. 위치 요청이 실패해도 이미 보고 있던 지역 지도는 유지하며, 직접 진입의 위치 거부·오류·8초 시간 초과 시에는 안내한다. 좌표는 후보 조회에만 사용하고 브라우저 저장소나 스캔 기록에는 저장하지 않는다.

## 입점 식당의 촬영 없는 메뉴 확인

홈/지도/촬영 화면의 식당 선택에서 입점 파트너를 고르면 `/restaurants/:id/menu`로 이동한다. 가상 전체 레시피 6종과 현재 프로필을 비교해 기존 결과 카드로 보여준다. 확인된 회피 재료 충돌은 위험, 프로필 없음·종교 인증 확인 필요는 주의로 표시한다. 확률을 임의로 만들지 않는다. 이 동선은 실제 스캔 API를 호출하지 않는다.

하단은 ‘프로필 수정하기 / 기록하기’. 식당이 연결된 상태로 기존 저장 흐름을 재사용한다. 일반 식당은 촬영 흐름을 유지한다. 기록 자체 페이지는 삭제하지 않고 마이페이지에서 계속 접근한다.

## 스캔 전

홈의 스캔 CTA는 식당 선택 시트를 한 번 제시한다. 주변/지역 후보를 누르거나 한글·영문 이름으로 검색한다. “식당 없이 계속하기”로 즉시 넘어갈 수 있다. 하단 촬영 탭에서는 `/scan`으로 직접 들어가고 화면 위 선택 행에서 식당을 연결할 수 있다.

카메라 열기/사진 선택 → 미리보기 → 분석 시작. 실서비스 모드의 카메라 권한 거부, 파일 형식/10MB 제한, 업로드 재시도 처리는 기존 동작을 유지한다.

일반 스캔은 사진 선택/촬영 → 업로드 티켓 발급·S3 PUT → 백엔드 분석 시작 → 분석 화면의 상태 폴링 → 실제 결과로 이동한다. 명시적 데모 모드는 업로드/분석 요청 없이 기존 분석 화면을 약 4.2초 표시한 뒤 분식 13개·비건/새우 결과로 이동한다. 시연 중 취소하면 타이머를 정리하며 계정 프로필은 유지한다. 자세한 내용은 `scan-result-filming.md`를 참조한다.

마이페이지의 지도 언어 선택은 ‘설정’ 탭에 있다. 앱 언어와 독립적으로 기기에 저장하며 식단 프로필이 없어도 변경할 수 있다.

## 결과

식당이 연결된 결과는 식당 이름을 가장 큰 제목으로, 연결되지 않은 결과는 일반 메뉴 가이드 제목으로 표시한다. 요약과 적용 프로필 → 상태별 개수/필터 → 메뉴명·가격·찜 → 원인 재료 칩과 직원 확인·주문 카드 → 펼쳐 보는 이유·주의 재료 포함 가능성·근거 순서다. 카드의 판정 이유와 상세 근거는 접힌 상태에서 숨기고, 위험 카드에는 채운 주 버튼을 두지 않는다. 큐레이션은 메뉴 목록 끝에서만 제공한다. 메뉴판 사진 URL이 아직 없으면 사진 보기 버튼은 비활성화한다.

방금 촬영하거나 선택한 메뉴판 사진은 현재 결과 화면에서 확대해 볼 수 있다. 브라우저 임시 URL이므로 결과 화면을 떠나면 해제한다. 서버 스캔 상세에 사진 URL이 아직 없어서 기록을 다시 열었을 때는 사진 보기 버튼을 비활성화한다. 원인 재료 칩은 좁은 화면에서 다음 줄로 넘어간다.

메뉴 하트는 토글이며 마이페이지 → 저장한 메뉴에서 메뉴명·판정 결과·연결 식당(있는 경우)을 확인한다. 찜은 스캔 기록과 별도로 저장한다. 서버 스캔은 `scanId + displayOrder`를 메뉴 식별자로 사용하고, 시연 메뉴는 기록/결과 인스턴스별 키를 쓴다.

확률은 재료의 포함 가능성이다. 식사의 안전 확률이나 알레르기 반응 확률이 아니다. 직원 답변으로 결과 상태를 자동 덮어쓰지 않는다.

## 저장

하단의 같은 크기 버튼: “다시 스캔하기” / “기록하기”. 기록하기 → 비공개 스캔 기록 저장 완료 → 스캔 기록. 공개되는 식사 후기는 결과 상세·식당 상세에서 별도 작성한다. 스캔 시작 전에 선택한 식당은 해당 분석의 컨텍스트이므로 결과 저장 단계에서 변경하거나 해제하지 않는다. 식당 없이 시작한 스캔에서만 “식당 연결하기 · 선택”을 노출한다.

- 식당 있음: 방문 기록 이름, restaurantId, 메뉴, 프로필 스냅샷, 선택형 피드백 저장.
- 식당 없음: 일반 스캔 이름, restaurantId=null, 메뉴와 프로필 스냅샷 저장. 식당 피드백은 없음.
- 저장을 반복하면 같은 recordId를 갱신한다. 식당이 바뀌면 입력 중인 후기를 비운다.
- 기록 상세를 다시 열면 당시의 프로필과 메뉴를 사용한다.
- 기록 이름 수정/삭제 가능. 서버 스캔과 로컬 방문 메타데이터는 구분한다.
- 기록 이름은 255자 이내로 수정하며 서버 저장이 성공한 뒤 목록에 반영한다. 실패하면 입력 상태와 재시도 안내를 유지한다.
- 식당 지정 여부와 무관하게 같은 제목 수정 UI를 사용한다. 같은 식당 재스캔은 이전 결과를 덮어쓰지 않고 새 `scanId`/기록으로 저장하며, 목록에는 스캔 시각을 표시한다.

## 후기와 추천 동선(후속 화면 작업 기준)

식당 상세의 「후기 작성」 또는 마이페이지 → 스캔 기록 상세의 「식당 후기 작성」으로 진입한다. 식당이 없는 기록은 먼저 식당을 선택한다. 후기는 스캔 기록이 아닌 식당에 연결하고, 마이페이지 → 내가 작성한 후기에서 같은 후기 UI를 재사용한다. 메뉴를 하나 이상 선택하고 현재 프로필 항목에 대해 있/없/모름을 선택적으로 답하며 메뉴별 메모는 500자까지 남긴다. 본인 후기는 수정·삭제, 타인 후기는 신고만 허용한다. 신고 사유는 부적절한 내용·허위 정보·광고·스팸·기타이며 신고 시 후기 ID·신고자 ID·사유·시각을 저장한다. 접수만으로 후기를 숨기지 않고 관리자 검토를 기다린다. 관리자 화면은 이 범위에 없다. 시연 후기는 브라우저에만 저장하고 가상 방문자 후기는 `src/app/demo/reviews.ts`에 둔다.

후기 메모가 500자를 넘으면 해당 메뉴 아래 초과 글자 수를 알리고 저장 버튼을 비활성화한다.

동네 추천은 위치가 있으면 가까운 거리순으로, 거리가 50m 이내로 비슷하면 후기 수를 보조 기준으로 정렬한다. 위치가 없으면 후기 많은 순을 기본값으로 한다. 현재 시연 지도는 fixture의 선택형 후기 집계 수로 이 규칙을 보여준다. 운영 가게 후보 응답에는 작성된 후기 수가 포함되며, 위치 대신 지역 중심을 쓰는 홈 추천은 후기 많은 순으로 표시한다.

실제 `scanId`가 있는 스캔은 서버의 멱등 `PUT /api/v1/scans/:scanId/record`로 저장한다. 스캔 때 선택한 식당은
요청에서 다시 보내지 않고, 식당 없이 시작한 경우에만 저장 시 선택한 `storeId`와 `storeMatchMethod`를 함께 보낸다.
서버 저장이 실패하면 완료 화면이나 로컬 기록으로 대체하지 않고 같은 화면에서 재시도한다. 명시적 데모의 고정 결과,
파트너 메뉴, 기존 로컬 기록처럼 서버 스캔 리소스가 없는 흐름만 브라우저 저장을 유지한다.

## 미래 방문 확인

지역 후보 선택은 장소 연결이며 방문 인증은 아니다. 동의 기반 위치 후보와 현장 QR의 조합을 후속 구현한다. QR은 식당 ID를 채우는 것과 서버에서 방문을 검증하는 것을 별개로 설계한다.
