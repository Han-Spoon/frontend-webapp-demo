# 사용자 흐름

## 시작과 로그인

1. `/` 랜딩에서 한스푼의 메뉴 번역·식단 확인·직원 소통 가치를 확인한다.
2. “한스푼 시작하기”를 눌러 `/login`으로 이동한다.
3. Google 계정으로 로그인한다. 연령 선택과 보호자 승인 단계는 없다(명세 V2, 2026-11-16 되돌림). 이메일·비밀번호 회원가입과 다른 소셜 로그인은 제공하지 않는다.
4. 서버에서 최신 약관 동의 상태를 확인한다. 필수 서비스 이용약관·개인정보 수집·이용·민감정보 처리 동의가 없으면 `/terms`로 이동한다.
5. 필수 문서마다 끝까지 읽고 개별 동의한다. 「전체 동의」는 읽지 않은 필수 문서를 순서대로 열고, 모두 동의하면 선택 마케팅 항목까지 켠다. 선택 항목은 별도 토글·본문 보기와 거부가 가능하다.
6. 서버에 문서 버전과 4개 동의 결정을 저장한 뒤, 기존 프로필이 있으면 홈으로, 없으면 온보딩으로 이동한다. 저장 실패 시 다음 단계로 진행하지 않는다.

랜딩과 로그인에서 언어를 바꿀 수 있고 선택은 두 화면과 이후 앱에 이어진다. Google ID Token만 `/api/v1/auth/google`로 전달한다.

마이페이지 설정에서 약관 본문을 다시 볼 수 있다. 선택 동의를 바꾸거나 철회할 수 있다. 서버가 동의 버전을 바꾸면 재동의가 필요하다. 온보딩은 언어 → 국가 → 식단 3단계이며, 식단에 해당 사항이 없으면 「해당 없음」을 선택한다.

## 로그인 없는 시연 동선

랜딩 또는 로그인 화면의 「로그인 없이 시연하기」는 Google 계정을 묻지 않고 데모 약관 → 온보딩 → 홈으로 이어진다. 데모에서 고른 약관 결정은 서버에 전송하지 않는다. 프로필과 기록은 `src/app/demo/`의 fixture 및 이 브라우저의 로컬 저장소만 사용한다. 새 시연을 시작하면 이전 데모 프로필과 기록을 초기화하고, 온보딩 완료 후 프로필은 새로고침해도 유지된다. 시연 지도는 외부 지도 키 없이 fixture 위치 개요와 선택 가능한 식당 핀을 보여준다. 로그인 화면의 「Google 로그인으로 전환」은 데모 세션을 종료하고 기존 운영 동선으로 돌아간다. 이 동선은 실제 개인정보 처리 동의 절차를 대신하지 않는다.

## 식당을 찾는 중

1. 홈에서 5개의 식당 소개/문화 콘텐츠 캐러셀을 본다. 캐러셀은 5초마다 자동 이동하며 모션 감소 설정에서는 자동 이동하지 않는다.
2. 홈에서 청담·부산·강남/역삼 등 18개 지역 칩을 선택하고, 해당 지역 중심 주변의 실제 가게를 지도에서 확인한다. 처음 진입하면 첫 버튼인 청담이 선택되며 일반/데모 홈 모두 동일하다.
3. 홈의 지도 핀으로 가게를 바꾸고, 선택 가게 카드나 전체 지도 버튼에서 같은 검색 중심을 유지한 채 풀스크린 `/map`으로 이동한다.
4. 풀스크린 지도(`/map`)는 아래 탭 바 없이 지도 전체를 쓰고, 뒤로 버튼은 이전 화면(직접 열었으면 홈)으로 돌아간다.
   - 운영 지도: 아래 목록 시트(접힘/펼침, 손잡이를 끌거나 누름). 핀이나 이름을 누르면 목록 대신 단일 가게 카드가 뜨고, 옆으로 넘길 때마다 넘긴 가게가 선택되어 핀 강조와 지도 중심이 그 가게로 옮겨 간다. 카드 위 왼쪽 끝의 원형 목록 버튼으로 돌아간다.
   - 목록 맨 위(제목 줄 없음): 정렬 버튼 하나 [기본순 ▾]를 누르면 드롭다운에서 기본순(서버 순서, 검증 가게 먼저. 개인화·안전 순위 아님)·거리순·리뷰 많은순을 고른다. 이름 검색 중에는 거리가 없어 거리순을 숨긴다. 접힌 목록에서는 메뉴가 위로, 펼친 목록에서는 아래로 열린다. 이어서 가로 스크롤 음식 종류 [전체]·[🍚 한식]·[🥩 고기]·[🐟 횟집·해물] 등. 음식 종류는 지금 결과에 있는 것만 버튼으로 보이고, 고르면 목록·지도 핀·카드에 모두 적용된다. 분류는 후보의 업종 코드 `categoryCode`(소상공인 상권업종 분류: 상가정보 가게는 한식 소분류와 분식, LOCALDATA 가게는 중분류·대분류)를 표로 묶은 것이다(`discovery/foodCategories.ts`). 한식(백반/한정식·전/부침개·LOCALDATA 한식), 국·탕·찌개, 고기(돼지·소·닭/오리·족발/보쌈·곱창), 횟집·해물(횟집·해산물·복), 국수·냉면, 분식(김밥/만두/분식, LOCALDATA 분식), 중식, 일식, 양식. 기타 한식 음식점·대분류 '음식'·표에 없는 코드는 기타. 코드가 없을 때만 같은 표의 분류 이름으로 찾는다. 그림 문자는 장식이라 스크린리더에는 읽히지 않는다.
   - 핀: 초록 원형 핀 아래에 가게 이름(배경 없이 흰 테두리 글자, 두 줄까지). 같은 건물 묶음은 핀 안에 가게 수. 이름 자리가 없으면 핀만. 선택 가게는 핀 대신 주황 말풍선(꼬리가 위치를 가리킴, 묶음이면 `+N`).
   - 가게 카드: 가게명(누르면 후기가 있는 상세 시트), 별점(후기 수) 또는 후기 수, 지역(도로명 주소의 구·군)·분류(기타는 한국어 화면에서만 원래 분류 이름, 다른 언어는 숨김)·층, 내 위치(또는 지도 중심)에서 거리, 운영시간, 사진(선택), 저장, [이 식당 메뉴 스캔]. 층은 후보의 `floorInfo` 원본 값을 7개 언어 문구로 바꾼다(`discovery/storeFloor.ts`: "1" → 1층·1F, "B1" → 지하 1층·B1, "지" → 지하, "반"·"반지층" → 반지하). 빈 값·필드 없음(배포 전 서버)·"0"·그 밖의 값은 숨긴다. 별점·운영시간·사진은 후보 API에 없어 값이 없으면 숨긴다(개발용 `/dev/map-preview`만 fixture로 채움). 저장은 이 기기에만 기억한다.
   - 같은 건물(5m 이내) 가게는 핀 하나로 묶고, 카드에서는 서로 이웃한다.
   - 시연 지도: 운영과 같은 전체 지도(지역 태그·목록 시트·카드 넘기기·정렬·음식 종류)를 쓰되, 지도는 외부 키 없는 시연용 위치 개요(끌기·[이 지역에서 검색] 없음)다. 가상 식당(`src/app/demo/restaurants.ts`)을 후보 형식으로 바꿔(`src/app/demo/mapDemoStores.ts`) 지역 중심 반경 1.5km 안을 레시피 인증 식당 먼저, 가까운 순으로 최대 20곳 보여 준다. 카드에는 입점·레시피 인증 배지와, 인증 식당은 [내 프로필로 메뉴 보기], 그 밖은 [이 식당 메뉴 스캔]. 가게명을 누르면 기존 상세 시트(같은 프로필의 경험·후기). 홈에서 식당을 골라 오면 그 지역 중심에서 그 식당 카드와 상세를 연다. 저장은 카드의 북마크로 통일해 상세의 하트는 뺐다.
5. 상세에서 입점/전체 레시피 인증 여부, 같은 프로필의 후기, 찜을 확인한다. 입점 식당은 ‘내 프로필로 메뉴 보기’, 그 외에는 ‘이 식당 메뉴 스캔’으로 이어진다.
6. 홈 하단 ‘한 끼가 여행이 되는 곳’에서 선택한 동네의 실제 식당 후보를 사진 카드로 둘러본다. 최대 6곳의 상호·업종·주소를 보여주며 클릭하면 해당 식당이 선택된 지도로 이동한다. 개인화/안전 순위가 아니며 현재 사진은 표시된 메뉴·공간 참고 이미지다. 상세 정책은 `restaurant-recommendations.md`를 따른다.

홈은 지역 칩에 대응하는 중심 좌표를 `POST /api/v1/stores/candidates`에 보내 반경 1km의 실제 가게를 최대 20곳 조회하며 위치 권한을 요구하지 않는다. 홈에서 `/map`으로 이동하면 전달받은 지역 중심 좌표로 즉시 시작하고, 하단 지도 탭에서 직접 `/map`에 진입한 경우에만 브라우저 현재 위치를 먼저 조회한다. 전체 지도의 검색창 바로 아래에는 외국인 방문이 많은 서울 지역 태그(명동·남대문, 종로·광화문, 을지로·동대문, 홍대·연남, 이태원·한남, 용산, 성수·건대, 강남역, 신사·압구정, 코엑스·삼성, 잠실, 여의도)가 가로 스크롤로 있고, 누르면 그 지역 중심 좌표로 후보를 조회하며(이름 검색 중이면 검색어를 지움) 지금 결과의 지역 태그를 강조한다. 목록을 펼쳐도 검색창과 지역 태그는 가리지 않는다. 전체 지도에서 지도를 옮기면 바로 다시 조회하지 않고 목록 바로 위 가운데에 [이 지역에서 검색]을 띄우며, 누르면 그 중심 좌표로 후보를 조회한다. 후보 응답으로 지도 위치를 다시 맞추지 않아 요청이 반복되는 것을 막는다. 목록 바로 위 오른쪽의 [내 주변]은 현재 위치로 조회(이미 현재 위치 결과면 지도만 되돌림)하고, 현재 위치가 아직 없으면 그 시점에 위치 권한을 요청한다. 위치 요청이 실패해도 이미 보고 있던 지역 지도는 유지하며, 직접 진입의 위치 거부·오류·8초 시간 초과 시에는 안내한다. 좌표는 후보 조회에만 사용하고 브라우저 저장소나 스캔 기록에는 저장하지 않는다.

## 입점 식당의 촬영 없는 메뉴 확인

홈/지도/촬영 화면의 식당 선택에서 입점 파트너를 고르면 `/restaurants/:id/menu`로 이동한다. 가상 전체 레시피 6종과 현재 프로필을 비교해 기존 결과 카드로 보여준다. 확인된 회피 재료 충돌은 위험, 프로필 없음·종교 인증 확인 필요는 주의로 표시한다. 확률을 임의로 만들지 않는다. 이 동선은 실제 스캔 API를 호출하지 않는다.

하단은 ‘프로필 수정하기 / 기록하기’. 식당이 연결된 상태로 기존 저장 흐름을 재사용한다. 일반 식당은 촬영 흐름을 유지한다. 기록 자체 페이지는 삭제하지 않고 마이페이지에서 계속 접근한다.

## 스캔 전

홈의 스캔 CTA는 식당 선택 시트를 한 번 제시한다. 주변/지역 후보를 누르거나 한글·영문 이름으로 검색한다. “식당 없이 계속하기”로 즉시 넘어갈 수 있다. 하단 촬영 탭에서는 `/scan`으로 직접 들어가고 화면 위 선택 행에서 식당을 연결할 수 있다.

카메라 열기/사진 선택 → 미리보기 → 분석 시작. 실서비스 모드의 카메라 권한 거부, 파일 형식/10MB 제한, 업로드 재시도 처리는 기존 동작을 유지한다.

일반 스캔은 사진 선택/촬영 → 업로드 티켓 발급·S3 PUT → 백엔드 분석 시작 → 분석 화면의 상태 폴링 → 실제 결과로 이동한다. 명시적 데모 모드는 업로드/분석 요청 없이 기존 분석 화면을 약 4.2초 표시한 뒤 분식 13개·비건/새우 결과로 이동한다. 시연 중 취소하면 타이머를 정리하며 계정 프로필은 유지한다. 일반 스캔은 취소를 확인하면 진행 중인 스캔을 삭제한다(`DELETE /api/v1/scans/{scanId}`). 자세한 내용은 `scan-result-filming.md`를 참조한다.

분석 요청이 네트워크·서버 오류로 실패하면 원시 오류 문구 대신 재시도 안내를 보여준다. 서버가 사진이나 저장 키를 거부한 경우에는 같은 요청을 반복하지 않고 새 사진을 선택하도록 안내한다.

마이페이지의 지도 언어 선택은 ‘설정’ 탭에 있다. 앱 언어와 독립적으로 기기에 저장하며 식단 프로필이 없어도 변경할 수 있다.

## 결과

식단 조건이 하나도 없으면(온보딩에서 「해당 없음」) 위험·주의 배지와 판정 필터 없이 재료만 보여 주고, 식단 칸에서 이유와 「식단 설정하기」(온보딩 식단 단계)를 안내한다. 이때도 위험·주의 판정이 하나라도 있으면 배지와 필터를 숨기지 않는다. 식단 정보를 불러오지 못한 경우(프로필 `null`)는 '식단 없음'으로 보지 않고, 받은 판정을 그대로 보여 주며 "내 식단 정보를 불러오지 못했어요"를 표시한다. 홈에는 식단 조건이 없는 사용자에게만 식단 설정 카드를 보여 주고, 「닫기」는 이 기기에 기억한다.

식당이 연결된 결과는 식당 이름을 가장 큰 제목으로, 연결되지 않은 결과는 일반 메뉴 가이드 제목으로 표시한다. 요약과 적용 프로필 → 상태별 개수/필터 → 메뉴명·가격·찜 → 원인 재료 칩과 직원 확인·주문 카드 → 펼쳐 보는 이유·주의 재료 포함 가능성·근거 순서다. 카드의 판정 이유와 상세 근거는 접힌 상태에서 숨기고, 위험 카드에는 채운 주 버튼을 두지 않는다. 큐레이션은 메뉴 목록 끝에서만 제공한다. 직원 답변은 서버에 저장한 뒤 결과를 다시 조회한다.

방금 촬영하거나 선택한 메뉴판 사진은 현재 결과 화면에서 확대해 볼 수 있다. 브라우저 임시 URL이므로 결과 화면을 떠나면 해제한다. 기록을 다시 열면 `GET /api/v1/scans/{scanId}/image`로 사진을 불러오며, 보관 기한이 지나면(410) 볼 수 없다고 안내한다. 원인 재료 칩은 좁은 화면에서 다음 줄로 넘어간다.

메뉴 하트는 토글이며 마이페이지 → 저장한 메뉴에서 메뉴명·판정 결과·연결 식당(있는 경우)을 확인한다. 찜은 스캔 기록과 별도로 저장한다. 서버 스캔은 명세 V2의 `scanMenuId`를 메뉴 식별자로 사용하고, 시연 메뉴는 기록/결과 인스턴스별 키를 쓴다.

확률은 재료의 포함 가능성이다. 식사의 안전 확률이나 알레르기 반응 확률이 아니다. 직원 답변은 명세에 따라 서버에서 판정을 갱신하며, 프런트는 서버 결과를 다시 읽는다.

## 저장

하단의 같은 크기 버튼: “다시 스캔하기” / “기록하기”. 기록하기 → 비공개 스캔 기록 저장 완료 → 스캔 기록. 공개되는 식사 후기는 결과 상세·식당 상세에서 별도 작성한다. 스캔 시작 전에 선택한 식당은 해당 분석의 컨텍스트이므로 결과 저장 단계에서 변경하거나 해제하지 않는다. 식당 없이 시작한 스캔에서만 “식당 연결하기 · 선택”을 노출한다.

- 식당 있음: 방문 기록 이름, restaurantId, 메뉴, 프로필 스냅샷 저장. 서버 기록 요청에는 식단 답변을 보내지 않으며, 식단 답변은 식사 후기 API로 보낸다.
- 식당 없음: 일반 스캔 이름, restaurantId=null, 메뉴와 프로필 스냅샷 저장. 식당 피드백은 없음.
- 저장을 반복하면 같은 recordId를 갱신한다. 식당이 바뀌면 입력 중인 후기를 비운다.
- 기록 상세를 다시 열면 당시의 프로필과 메뉴를 사용한다. 서버 기록은 `dietSnapshot`(스캔 당시 식단)을 판정 기준으로 보여 주고, 스냅샷이 없는 옛 스캔은 현재 식단 대신 “판정 기준 식단 확인 불가”를 표시한다.
- 기록 이름 수정/삭제 가능. 서버 스캔과 로컬 방문 메타데이터는 구분한다.
- 기록 이름은 1–30자로 수정하며(명세 V2) 서버 저장이 성공한 뒤 목록에 반영한다. 실패하면 입력 상태와 재시도 안내를 유지한다.
- 식당 지정 여부와 무관하게 같은 제목 수정 UI를 사용한다. 같은 식당 재스캔은 이전 결과를 덮어쓰지 않고 새 `scanId`/기록으로 저장하며, 목록에는 스캔 시각을 표시한다.

## 후기와 추천 동선(후속 화면 작업 기준)

식당 상세의 「후기 작성」 또는 마이페이지 → 스캔 기록 상세의 「식당 후기 작성」으로 진입한다. 식당이 없는 기록은 먼저 식당을 선택한다. 후기는 스캔 기록이 아닌 식당에 연결하고, 마이페이지 → 내가 작성한 후기에서 같은 후기 UI를 재사용한다. 메뉴를 하나 이상 선택하고 현재 프로필 항목에 대해 있/없/모름을 선택적으로 답하며 메뉴별 메모는 500자까지 남긴다. 본인 후기는 수정·삭제, 타인 후기는 신고만 허용한다. 신고 사유는 부적절한 내용·허위 정보·광고·스팸·기타이며 신고 시 후기 ID·신고자 ID·사유·시각을 저장한다. 접수만으로 후기를 숨기지 않고 관리자 검토를 기다린다. 관리자 화면은 이 범위에 없다. 시연 후기는 브라우저에만 저장하고 가상 방문자 후기는 `src/app/demo/reviews.ts`에 둔다.

식당 상세 후기 목록은 메뉴 하나와 현재 프로필의 식단 항목 여러 개로 좁혀 볼 수 있다. 필터의 개수는 해당 후기가 몇 개인지 나타내며, 조건에 맞는 후기가 없을 때는 필터를 초기화할 수 있다. 실서비스 후기 조회와 마이페이지 내 후기 조회가 실패하면 재시도 버튼을 제공한다. 신고 요청 중에는 같은 사유를 중복 제출하지 못하게 한다.

마이페이지의 프로필 탭은 언어·나라·식단에서 실제 선택된 값만 카드로 요약하고 각 항목을 따로 수정한다. 저장한 메뉴와 내가 작성한 후기 진입은 그 아래에 둔다. 저장한 메뉴 조회 실패는 빈 목록으로 처리하지 않고 재시도할 수 있게 표시한다. 조회 중·실패·결과 없음은 서로 구분한다.

브라우저가 오프라인으로 전환되면 큐레이션·마이페이지·스캔 기록·저장한 메뉴·내 후기의 상단에 공통 오프라인 안내를 표시한다. 연결이 돌아오면 안내가 사라지며, 저장한 메뉴와 내 후기는 안내의 「다시 시도」로 조회를 다시 요청할 수 있다.

홈·큐레이션 상세·직원 카드에도 같은 오프라인 안내를 표시한다. 홈 지도 미리보기와 전체 지도에서 가게 후보 조회가 실패하면 현재 검색 좌표를 유지한 채 「다시 시도」로 재조회한다. 전체 지도 상세의 후기 조회 실패 화면은 후보 응답에 있던 후기 수를 유지하고, 실제 후기 목록은 다시 조회한 뒤 표시한다. 직원 카드 조회 실패는 빈 목록과 구분해 오류와 재시도를 보여준다.

시연 결과의 「자주 쓰는 카드로 저장」은 시연 저장소의 카드 목록으로 이어지고 서버 카드 API를 호출하지 않는다. 새 시연을 시작하면 시연 카드도 초기화한다. 운영 계정의 카드는 기존 서버 API를 그대로 사용한다.

마이페이지 설정은 지도 언어 2×2 선택 카드, 알림·동의 상태, 계정 관리 순서다. 운영 계정의 마케팅 동의 상태는 `GET /api/v1/consents/me`에서 읽고 실패하면 확인 필요와 재시도를 표시한다. 시연에서는 서버 동의 상태를 조회하지 않고 시연용 선택으로 표시한다. 설정의 수정 버튼은 기존 약관·동의 화면으로 이동한다.

후기 메모가 500자를 넘으면 해당 메뉴 아래 초과 글자 수를 알리고 저장 버튼을 비활성화한다.

동네 추천은 위치가 있으면 가까운 거리순으로, 거리가 50m 이내로 비슷하면 후기 수를 보조 기준으로 정렬한다. 위치가 없으면 후기 많은 순을 기본값으로 한다. 운영 가게 후보 응답에는 작성된 후기 수가 포함되며, 위치 대신 지역 중심을 쓰는 홈 추천은 후기 많은 순으로 표시한다.

실제 `scanId`가 있는 스캔은 서버의 멱등 `PUT /api/v1/scans/:scanId/record`로 저장한다. 스캔 때 선택한 식당은
요청에서 다시 보내지 않고, 식당 없이 시작한 경우에만 저장 시 선택한 `storeId`와 `storeMatchMethod`를 함께 보낸다.
서버 저장이 실패하면 완료 화면이나 로컬 기록으로 대체하지 않고 같은 화면에서 재시도한다. 명시적 데모의 고정 결과,
파트너 메뉴, 기존 로컬 기록처럼 서버 스캔 리소스가 없는 흐름만 브라우저 저장을 유지한다.

### 결과 근거 표시 정리 (2026-11-23)

주의 재료의 원형 그래프 숫자는 소수 둘째 자리에서 반올림해 소수 첫째 자리까지 표시한다. 원본 확률과 표시 허용 조건은 유지한다. 근거 충분도·추정 기준은 별도 반복 목록 대신 ‘재료별 근거’ 안의 해당 재료에 모아 표시하며, 포함 확률과 다르다는 설명은 섹션에서 한 번 제공한다. 기존 번역 문구와 7개 언어 fallback·아랍어 RTL을 유지한다.
